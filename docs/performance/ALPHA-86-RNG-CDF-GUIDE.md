## 改动与正确性依据

alpha.85 先计算 `value=rng*total`，再用 `value/total` 选择 guide 桶，保守扩宽区间，并读取端点检查回退。alpha.86 用同一次 LCG 更新后的 `seed>>24` 直接定位桶；这恰为 24-bit RNG 的高 8 位，不消耗新随机数。

令 `b=seed>>24`、原随机数为 `u`，则 `b/256 <= u < (b+1)/256`。同一个有限非负 `total` 上，浮点乘法和 CDF upper-bound 均单调，因此以 `upperBound(float32(b/256*total))` 和 `upperBound(float32((b+1)/256*total))` 作为 lo/hi，仍包含原搜索结果，即使乘法舍入后相等也成立。运行时保留原 `prefix<=value` 搜索和零功率分支；零 row total 使用原全区间。此保证依赖 guide 来自同帧、同一 CDF/total，不能复用旧帧表或近似构建。

guide 仍为 256×129 RGBA32F，新增 528384B。生产可用的 fragment pass 在原 cells/rows 完成后读取同一纹理，生成精确 lo/hi，并按命令顺序复制到本帧 assets。没有 CPU 下载或新增手工 barrier。A 不生成 guide，B 计入生成/复制；相同扩展容量。新方案减少除法、端点访问/分支及索引区间宽度，PDF、方向映射、发光纹理、BSDF、MIS 和 reservoir 顺序均未改。

1809156 组 float32 契约检查覆盖 CDF 长度 1/2/3/127/128/129/255/256/257、均匀/全零/单峰/稀疏/HDR/次正规数，以及每个桶边界的相邻 24-bit RNG，零不匹配。它是 CPU 算术契约，不冒充 GPU 覆盖。另在捕获的真实 CDF 上，GPU 调用原版和候选生产函数比较 1048576 个种子：方向逐位差异 0，RNG 差异 0。此 GPU 检查仅代表捕获环境。
